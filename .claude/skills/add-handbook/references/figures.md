# 図を描く

## 方針

eli5 の方針（大きな絵と少ない言葉）で、何も知らない読者が絵を見ただけで構造や流れをつかめる図を描く。eli5 は HTML の Artifact を作る指示を含むが、ここでは方針だけを借り、図は本の中の SVG として描く。

図にするのは、文章だけでは頭の中で組み立てにくいものである。

- 配置: タスク名を `:` で区切った部分が、そのまま一覧の階層になる
- 流れ: 取ってくる、並べる、移る
- 前後の比較: シェルスクリプトに散らばったコマンドと、`acme.toml` にまとまったタスク
- 形の違い: `acme init` と `acme init --minimal` が作るディレクトリの形
- 判定の順番: 設定ファイルを探すときに調べる場所の順番

コマンドとその出力で見せれば足りるものは、図にしない。飾りの図も描かない。目安は章の入り口に 1 枚で、40 ページ弱の本なら 10 枚ほどになる。

## 置き方

```markdown
![タスク名を「:」で区切った部分が、そのまま一覧の階層になる](../images/task-tree.svg)
```

- 概念を初めて出す段落の直後に置く。
- alt には、図が示していることを一文で書く。
- 図の内容は本文でも言葉で説明する。情報を図だけに置かない。
- `ja/styles/website.css` が SVG を中央に寄せ、ページの幅に合わせて縮める。

## SVG の約束

`$SKILL/assets/figure-skeleton.svg` を写して描き始める。文字のスタイル、フォルダーの記号、矢印の定義、背景のカードが入っている。

- 大きさ: `viewBox="0 0 720 H"`、`width="720" height="H"`。H は内容に合わせる（目安は 260〜390）。
- アクセシビリティ: `<svg>` に `role="img" aria-labelledby="title desc"` を付け、日本語の `<title>`（図の名前）と `<desc>`（図が示すこと）を書く。
- 背景: 角丸のカード（`#fffaf0`、`rx="20"`）を敷く。HonKit の夜間表示に切り替えても読める。
- 文字: 日本語はゴシック体、コマンドやパスは等幅のクラス（`.t`、`.m`）を使う。ラベルは 15〜19px、小さい注記でも 12px 以上にする。文ではなく、語か短い句にする。
- 色: 面は薄い色（`#fffaf0`、`#dce9ff`、`#d6e2f0`）、フォルダーは `#ffd98a` と `#d9a43a`、矢印は灰色（`#b0b0b0`）を使う。強調には青（`#3f7bdc`）と緑（`#2f9e6e`）を使い、1 枚の強調色は 2 色までにする。
- 外部の画像、フォント、スクリプトを使わない。
- ファイル名は中身を表す kebab-case にする（`task-tree.svg`、`config-lookup.svg`）。

## 確かめる

```console
$ "$SKILL/scripts/render_svg.sh" "$S/png" "$BOOK"/ja/images/*.svg
```

XML として正しいかを調べてから、viewBox の大きさで PNG にする。PNG を Read ツールで 1 枚ずつ見て、次を確かめる。

- 文字の重なり、はみ出し、切れ
- 余計な線や記号（例: パイプを表す縦棒が 1 本余っている）
- 注記と、それが指すものとの間隔
- 矢印の向きと、指している先

直したら描き直して、もう一度見る。最後に `check_book.py` の svg の項目（整形式、`role` と `<title>`、どのページからも使われていない図）を通す。ページに置いたときの見え方は、点検の最後に `shoot_pages.sh` で撮って確かめる。
